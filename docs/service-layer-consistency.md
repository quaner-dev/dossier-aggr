# Service 层一致性审核

本文记录 `services/` 层的代码一致性审核结果，并为后续新增和修改 service
提供约定。审核日期为 2026-08-20，范围包括 service 方法的委托方式、返回类型、
返回值处理、类型标注和文档字符串；不包含协议字段及数据库查询语义审核。

## 结论

当前 service 层的分层方向一致：业务方法通过 repo 完成数据访问，没有在 service
内直接创建数据库会话。但方法契约和表达方式仍存在几类不一致。

| 项目 | 当前状态 | 影响 | 建议 |
| --- | --- | --- | --- |
| 仅委托 repo 的返回写法 | 已统一 | 无行为影响 | 使用 `return await ...`，不引入仅用于立即返回的局部变量 |
| 调用方忽略返回值的写法 | 已统一 | 无行为影响 | 使用裸 `await ...`，不赋值给 `_` |
| 异步方法返回类型标注 | 已修复已知缺失 | 影响静态检查 | 所有公开 service 方法必须显式标注返回类型 |
| 集合返回契约 | 已统一 | 调用方可依赖可变列表 | service 边界统一为 `list[T]` |
| 人员和人脸的更新、删除结果 | 已统一 | service 不再丢弃 repo 结果 | 更新返回实体，删除返回标识 |
| 其他资源的更新和删除契约 | 部分存在领域差异 | 同类资源方法的调用方式可能不同 | 新增资源时遵循本文约定 |
| 方法文档字符串 | 尚未统一 | 主要影响可维护性 | 有业务语义的方法写说明；纯透传方法可依赖明确命名和类型 |

## 已统一的规则

### 直接返回 repo 结果

如果 service 不转换结果、不增加校验，也不执行其他业务动作，应直接返回 repo
调用结果：

```python
async def get_person(self, person_id: str) -> Person:
    return await get_person_repo(person_id=person_id)
```

只有在局部变量承担额外职责时才保留变量，例如转换、校验、审计记录或组合多个
repo 结果。变量名本身不构成保留理由。

### 调用方明确忽略返回值

当调用方只关心操作完成和异常传播、不需要使用 service 返回的实体或标识时，使用
裸 `await`：

```python
await service.delete_person(person_id)
```

不使用 `_ = await ...`。下划线赋值没有增加类型或运行时保障，也容易被误解为后续
仍会使用该值。

### 完整类型标注

所有公开 service 方法都应标注参数和返回类型。即使返回值可从实现推断，也不能
省略公开边界上的标注。此次审核补齐了 `APSService.update_aps() -> str`。

### 集合统一为 `list[T]`

service 的集合输出统一声明为 `list[T]`。repo 可以继续使用较宽的 `Sequence[T]`
返回类型，service 在边界通过 `list(await ..._repo())` 固化公开契约。方法的输入仍可
根据业务需要接受 `Sequence[T]`，输入类型较宽与输出类型稳定并不冲突。

## 更新和删除的返回值

人员和人脸 service 现在与 repo 契约一致：单项更新返回刷新后的实体，批量更新返回
实体列表，单项删除返回已删除 ID，批量删除返回已删除 ID 列表。其他资源原有的更新
和删除结果保持不变。

需要区分 ORM 操作与业务返回值：`await session.delete(entity)` 本身不提供删除结果；
删除是否成功由 `commit()` 完成或抛出异常表达。repo 在提交成功后主动返回 ID 或 ID
列表，service 再把这个业务结果返回给调用方。

新增方法遵循以下规则：

- 创建和更新返回持久化后的实体或实体列表，便于调用方获得数据库刷新后的值。
- 删除返回已删除标识或标识列表；若上层永远不需要确认明细，也可统一返回 `None`，
  但同一资源族必须一致。
- API 层仍负责将业务结果包装成协议响应，不将 repo 返回类型直接暴露为 HTTP 契约。

API 层可以在只需生成协议状态对象时忽略 service 返回值，但不应阻止 service 向其他
调用方提供完整的处理结果。

## 新增代码检查清单

1. service 只编排业务，不直接管理 `AsyncSession`。
2. 纯委托方法使用 `return await repo_function(...)`。
3. 调用方忽略返回结果时使用裸 `await`，不赋值给 `_`。
4. 需要转换为稳定集合契约时，使用 `return list(await repo_function(...))`。
5. 所有公开方法完整标注参数和返回类型。
6. 局部变量必须用于转换、校验、日志或后续业务逻辑，不能只用于下一行返回。
7. 改变 service 返回契约时同步更新 API 调用方、测试替身和 service 测试。
